## 1. 責務

F/Eは以下を担当する。

- 画面表示
- 条件入力
- 現在地取得
- `/api/search` 呼出
- ブロックシャッフル
- NG / OK処理
- 重複排除
- queue / セッション管理
- 条件緩和の段階管理
- 前回条件・履歴保存

HotPepper APIへ直接アクセスしない。HotPepperの予算コードを持たない。

## 9. スライダー実装

予算・距離の離散スライダーは `<input type="range">` をベースに実装する。

- `min=0 / max=options.length - 1 / step=1`
- 目盛りラベルはあくまで装飾とし、`aria-hidden="true"`
- `aria-valuetext` に表示ラベル（例: `4,000円以内`）を設定
- つまみのタップ領域は48px以上を確保
- フォーカスリングを消さない

カスタムdiv実装は行わない（キーボード操作とスクリーンリーダー対応のコストが見合わないため）。

## 12. NG

1. `currentShop.id` を `shownIds` へ追加
2. queueから次店舗を取り出す
3. 結果を更新
4. セッション保存
5. queue残数が8件以下、かつ `hasMore` なら追加検索
6. queueが空、かつ `hasMore === false` なら `noCandidate` 状態へ

## 13. OK

OKボタンは `<a>` 要素として実装する。

```tsx
<a
  href={currentShop.hotpepperUrl}
  target="_blank"
  rel="noopener noreferrer"
  onClick={handleOk}
>

</a>
```

`handleOk` は**同期処理のみ**で以下を行う。

1. 現在店舗を履歴へ保存
2. セッション更新

`window.open` を使ったプログラム遷移は行わない。非同期処理の後に呼ぶとiOS Safariでブロックされるため。

電話番号・メニュー・予約はHotPepper店舗詳細で確認する。

## 14. 候補なし

`noCandidate` は以下の2ケースで共通とする。

- 検索結果が0件で、続きもない（`hasMore === false`）
- 候補を出し切り、追加取得もできない

**そのページの候補が0件でも `hasMore` が真なら `noCandidate` にしない。** B/Eの予算絞り込みや重複排除はページ単位で全滅し得るため、そこで打ち切ると候補が残っているのに「候補なし」を出してしまう。スケルトンを出したまま次ページの先読みへ回す（§19・§20と同じ経路）。

```text
候補が見つかりませんでした

[ こだわり条件を外してさがす ]     ← relaxLevel に応じて文言が変わる

条件を変更
```

`relaxLevel` が4（全緩和済み）の場合は緩和CTAを出さず、「条件を変更」のみを表示する。

## 15. 条件緩和

```typescript
type RelaxLevel = 0 | 1 | 2 | 3 | 4;
```

| relaxLevel | 適用内容 | CTA文言 | 結果画面の通知 |
|---|---|---|---|
| 1 | preferences を全false | こだわり条件を外してさがす | こだわり条件を外して再検索しました |
| 2 | genreCode を null | ジャンルをおまかせにしてさがす | ジャンル指定を外して再検索しました |
| 3 | range を1段階拡大 | もう少し広い範囲でさがす | 範囲を2kmに広げて再検索しました |
| 4 | budgetMax を null | 予算の上限を外してさがす | 予算の上限を外して再検索しました |

- 緩和は累積する（relaxLevel=3 なら 1・2 の緩和も適用済み）
- **現在の条件を実際に変えない段階はスキップする**。`nextRelaxLevel(condition, level)` が、`level` より後ろで初めて条件が変わる段階を返す（変わる段階がなければ `null` ＝ CTAを出さない）
  - level 1: `preferences` がすべて false ならスキップ
  - level 2: `genreCode` が null ならスキップ
  - level 3: `range` が既に4（2km）ならスキップ
  - level 4: `budgetMax` が null ならスキップ
  - これがないと、こだわり未設定のまま「こだわり条件を外してさがす」を押すと**まったく同じ条件で再検索**され、条件は変わっていないのに緩和したように見える混乱が起きる
- 緩和・再試行での再検索は `shownIds` を引き継ぐ（同じ抽選の続きとして扱い、NGした店を再提示しない）。トップの「さがす」からの検索では捨てる
- 緩和は**ユーザーが明示的にCTAを押した場合のみ**適用する。自動緩和はしない
- 緩和した条件は `condition` 本体を書き換えず、`utils/relax.ts` の `applyRelax(condition, level)` で導出する（「条件を変更」でトップへ戻ったとき元の条件が見えるようにするため）

```typescript
function applyRelax(
  condition: SearchCondition,
  level: RelaxLevel
): SearchCondition;
```

## 19. 提示ロジック

```typescript
shuffleInChunks(shops: Shop[], chunkSize: number): Shop[]
mergeUniqueShops()
drawNextShop()
prefetchNextPage()
```

```text
初回: 50件（おすすめ順） → 表示済み/重複を除外 → 10件ブロック単位でシャッフル → queue → 1件表示
NG: current → shownIds → 次候補
prefetch: queue.length <= 8 && hasMore && !prefetching
このページが0件 & hasMore → スケルトンのまま次ページへ（上限はB/Eの MAX_START）
```

`shuffleInChunks` は配列を先頭から `chunkSize` 件ずつに区切り、**各ブロック内でのみ** Fisher-Yatesシャッフルを行う。これにより、HotPepperのおすすめ順（＝評判の良さと近さを反映した順序）を大枠で維持しつつ、毎回まったく同じ順序にならないようにする。

同時prefetchは1つまで（`prefetching` フラグで制御）。

## 20. 先読み中の候補切れ

prefetch中にNG連打でqueueが空になった場合:

- 結果カードをスケルトン表示に切り替える
- NG / OKボタンを無効化する
- prefetch完了後に次候補を表示する
- prefetchが0件で終わっても `hasMore` が真なら、続けて次ページを先読みする
- prefetchが0件で終わり `hasMore === false` になったら `noCandidate` へ

## 21. Geolocation

- **初回は「さがす」押下時**に取得を開始する。許可ダイアログが出るため、押下と同じ操作文脈で要求する
- **一度許可が済んでいれば、次回以降は起動時に先出しする**（`canPrimeLocation()`）。検索の待ち時間が縮む。ユーザー操作を伴わないので、先出しの失敗は画面に出さず「さがす」で取り直す
- 取得成功後はsessionStorageへ保持し、鮮度（`GEO_TTL_MS` = 5分）内なら再取得しない
- **鮮度切れの現在地は使わない**（`isGeoFresh()`）。`state.location` にも同じ判定をかける。1軒目から歩いたあとの再検索で古い地点を使わないため
- 失敗時は再試行CTAを表示する

先出しの可否判定:

| 許可実績（localStorage） | Permissions API | 先出し |
|---|---|---|
| なし | — | しない（初回はダイアログを出さない） |
| あり | `granted` | する |
| あり | `prompt` / `denied` | しない（あとから取り消された） |
| あり | 照会できない（Safari 等） | する |

現在地（座標）はsessionStorage以外へ保存しない。

## 22. 検索範囲の表示

検索範囲を以下の2箇所に表示する。

| 画面 | 位置 | 文言 |
|---|---|---|
| トップ | 「さがす」ボタンの直上 | 現在地から半径1km以内でさがします |
| 結果 / 候補なし | ヘッダー直下 | 現在地から半径1km以内 |

- 地図・座標は表示しない
- `range` の表示ラベル（300m / 500m / 1km / 2km）をそのまま使う
- 緩和で `range` が変わった場合は緩和後の値を表示する
- トップ画面での表示は、検索前に「どこを中心に探すのか」を示して不安を減らすことを目的とする

### 22.1 検索条件の表示

結果画面と候補なし画面に、**実際に検索に使った条件**（＝緩和を適用したあとの条件）を1行で表示する。緩和CTAを押したときに何が変わったのかを、ユーザーが自分で確認できるようにするため。

- 生成: `describeCondition(condition)` — `予算 / ジャンル / 距離 / こだわり` を ` / ` で連結する
  - 例: `4,000円以内 / おまかせ / 1km以内 / こだわりなし`
  - 予算未指定は `予算 指定なし`、こだわり未設定は `こだわりなし`、こだわり複数は `・` で連結
- 位置: 結果画面は緩和通知の下、候補なし画面は見出しの下
- 語の途中で折り返さないよう `word-break: keep-all` を指定する（区切りの空白でのみ折る）
- `App.tsx` で `applyRelax(condition, relaxLevel)` を一度だけ計算し、両画面に渡す

### セーフエリア

`env()` を直接使わず変数を経由する。ブラウザで値を差し替えてノッチ端末を再現・検証できるようにするため。

**高さを固定した要素に `padding-top: var(--safe-top)` を足さない。** `box-sizing: border-box` のもとでは padding が高さを食い潰し、ノッチ端末のPWAで中身が潰れる。`min-height: calc(本来の高さ + var(--safe-top))` を使う。

ヘッダーで実際にこの事故を起こした。`height: 58px` に約59pxの `padding-top` が入り、中身の高さが0になって本文と重なった。Safariのタブでは inset が0のため再現せず、PWAでのみ壊れる。

## 29. 合言葉

合言葉（`tsugidoko:passcode`）が未保存なら、条件設定の代わりに入力画面を出す。

```text
合言葉
[ ************ ]

このアプリは身内で使うため、合言葉が必要です。
一度入れればこの端末では次回から聞きません。

[ はじめる ]
```

- 入力は `type="password"`。空のままでは進めない（ボタンを無効化）
- 保存後はそのまま条件設定へ進む。次回起動時は聞かない
- `/api/search` が `403` を返したら保存値を破棄し、「合言葉が違います」を添えてこの画面へ戻す
- ヘッダー（メニュー・このアプリについて）はこの画面でも使える。HotPepperのデータを出さない画面なのでクレジットは置かない
- 検索の合言葉は `X-App-Token` ヘッダで送る（BE-001 §5）
