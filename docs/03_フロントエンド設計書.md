# 運命の1軒 — フロントエンド設計書

- 文書ID: FE-001
- 版: 1.0
- 更新日: 2026-09-19
- 技術: Vite + React + TypeScript

## 1. 責務

F/Eは以下を担当する。

- 画面表示
- 条件入力
- 現在地取得
- `/api/search` 呼出
- 候補shuffle
- NG / OK処理
- 重複排除
- queue / session管理
- 前回条件・履歴保存

HotPepper APIへ直接アクセスしない。

## 12. NG

1. `currentShop.id`を`shownIds`へ追加
2. queueから次店舗
3. 結果を更新
4. sessionStorage更新
5. queue残数が5件以下なら追加検索

## 13. OK

1. 現在店舗を履歴へ保存
2. session更新
3. `hotpepperUrl`を新しいタブで開く

電話番号・メニュー・予約はHotPepper店舗詳細で確認する。

## 14. 条件変更

- search画面へ戻る
- 現在条件を維持
- 再度「抽選する」で新sessionを開始

## 15. AppState

```typescript
interface AppState {
  screen: "search" | "result";
  condition: SearchCondition;
  location: GeoPoint | null;
  currentShop: Shop | null;
  queue: Shop[];
  shownIds: string[];
  nextStart: number;
  hasMore: boolean;
  loading: boolean;
  error: string | null;

```

`useReducer`を基本とする。

## 16. SearchCondition

```typescript
interface SearchCondition {
  budgetCode: string | null;
  genreCode: string | null;
  partySize: number;
  preferences: {

    midnight: boolean;
  };
  range: 1 | 2 | 3 | 4;
}
```

```text
POST /api/search
```

API I/F型は`shared/api-types.ts`を共有する。

## 18. 抽選

```typescript
shuffleShops()
mergeUniqueShops()
drawNextShop()
prefetchNextPage()
```

```text
初回: 20件 → shuffle → queue → 1件表示
NG: current → shownIds → 次候補
prefetch: queue.length <= 5 && hasMore
```

同時prefetchは1つまで。

- SVGへ`aria-label`
- 色だけで選択状態を表現しない
- Focusを削除しない
- コントラスト確保
- `prefers-reduced-motion`対応

## 24. エラー


## 25. PWA

`vite-plugin-pwa`を使用。

- アプリシェル: キャッシュ
- APIレスポンス: 永続キャッシュしない
- 店舗写真: 必須キャッシュにしない

## 26. F/Eテスト観点

- スライダーが離散値にスナップ
- ジャンル単一選択
- 人数1〜20
- Accordion開閉
- 抽選API多重送信なし
- 結果1店舗
- NGで重複なし
- queue残5件以下でprefetch
- OKで履歴保存 + HotPepper遷移
- 前回条件復元
- 位置情報拒否時の再試行
