# つぎどこ — テスト・CI設計書

- 文書ID: TEST-001
- 版: 1.0
- 更新日: 2026-09-19
- 対象: MVP

## 1. 方針

MVPでは、**壊れたら気づけない箇所**に絞ってテストを書く。

優先度:

1. 純粋関数（予算変換 / 距離計算 / シャッフル / 重複排除 / 緩和導出）
2. Workerのリクエスト境界（検証 / Origin / 外部APIエラー）
3. Storageの異常系（TTL / 破損 / 容量超過）
4. 主要なユーザー操作（さがす → NG → OK）

カバレッジ率を目標値として設定しない。上記4分類が網羅されていることを基準とする。

E2E（Playwright）はMVP対象外。Geolocationとポップアップ遷移を含む主要導線は手動確認とする（§8）。

## 2. ツール

| 対象 | ツール |
|---|---|
| Lint | ESLint（`typescript-eslint` / `eslint-plugin-react-hooks`） |
| Format | Prettier |
| 型検査 | `tsc --noEmit` |
| F/Eテスト | Vitest + jsdom + @testing-library/react |
| W/Eテスト | Vitest + `@cloudflare/vitest-pool-workers` |
| 外部APIモック | `msw`（F/E）/ `fetch` スタブ（Worker） |

Workerのテストは実runtime（workerd）上で動かす。Node環境でのエミュレーションはCloudflare固有の挙動を検証できないため。

## 3. 構成

```text
vitest.config.ts          # src/ 向け（jsdom）
vitest.worker.config.ts   # worker/ 向け（workers pool）
```

```jsonc
// package.json（抜粋）
{
  "scripts": {
    "dev": "vite",
    "dev:worker": "wrangler dev",
    "build": "npm run typecheck && vite build",
    "lint": "eslint .",
    "format:check": "prettier --check .",
    // tsconfigをF/E・Worker・ビルドスクリプトの3つに分ける。
    // WorkerはDOM型を持たず、生成されたworker-configuration.d.tsを使うため
    "typecheck": "tsc -p tsconfig.app.json --noEmit && tsc -p tsconfig.worker.json --noEmit && tsc -p tsconfig.node.json --noEmit",
    "test": "vitest run",
    "test:worker": "vitest run -c vitest.worker.config.ts",
    "cf-typegen": "wrangler types",
    "gen:budget": "tsx scripts/gen-budget-master.ts",
    "deploy": "wrangler deploy"
  }
}
```

### 依存関係のインストール

`npm install` ではなく **`npm ci`** を使う。npm 10系は本プロジェクトの依存関係（vitestのoptional peer）でideal treeの構築に失敗する。依存を追加・更新するときだけ `npx npm@11 install` を使い、生成された `package-lock.json` をコミットする。CIも `npm ci` を使う。

### Workerテストの設定

`@cloudflare/vitest-pool-workers` 0.22以降は `defineWorkersConfig` ではなく `cloudflareTest` プラグインを通常のVitest設定へ差し込む。同梱されるworkerdの対応上限に合わせて `compatibility_date` を決める必要がある（BAS-001 §12）。

### Prettierの対象外

`docs/` と `README.md` はPrettierの整形対象外とする。日本語を含む表のカラム幅計算が合わず、整形するとかえって読みにくくなるため。

## 4. B/Eテスト観点

### 入力検証（`validation.ts`）

- 正常系が通る
- `lat` が範囲外 / NaN / 欠落 → 400
- `lng` が範囲外 → 400
- `range` が0 / 5 / 文字列 → 400
- `budgetMax` が許可値以外（例: 3500） → 400
- `budgetMax` が `null` → 通る
- `includeUnknownBudget` が boolean 以外 / 欠落 → 400
- `genreCode` が未登録コード（例: `G999`） → 400
- `genreCode` が `null` → 通る
- `preferences` が boolean 以外 → 400
- `start` が0 / 小数 / 負数 → 400
- `start` が `MAX_START` → 通る / `MAX_START + 1` → 400

### Origin検証（`index.ts`）

- `Origin` が `ALLOWED_ORIGIN` と一致 → 処理される
- `Origin` が不一致 → 403
- `Origin` が欠落 → 403
- `GET /api/search` → 405
- `POST /api/unknown` → 404

### 予算絞り込み（`search.ts`）

- `includeUnknownBudget` の ON / OFF いずれでも、上限超過の店舗が落ちる
- ON では `budget` を送らず、OFF では送る

### 予算変換（`budget.ts`）

- `budgetMax = null` → 空配列（`budget` を送らない）
- `budgetMax = 2000` → 上限2,000円以下の帯のみを含む
- `budgetMax = 10000` → 上限10,000円以下の帯を含み、上限なしの帯を含まない
- 生成マスタの各エントリが `min <= max`（`max` が null でない場合）

`isWithinBudgetMax`:

- `budgetMax = null` → 常に true
- コードが空 → true（予算未登録の店を落とさない）
- マスタにないコード → true
- 上限以下のコード → true / 上限超過のコード → false

### 生成スクリプト（`gen-budget-master.ts`）

- 解析不能な `name` が含まれる場合に例外で終了する（無言で欠落させない）

### パラメータ組立（`hotpepper.ts`）

- `format=json` / `datum=world` / `count=50` / `order=4` が常に付く
- `party_capacity` を送らない
- `genreCode = null` のとき `genre` を送らない
- `budgetMax = null` のとき `budget` を送らない
- `includeUnknownBudget = true` のとき `budget` を送らない（予算未登録の店が除外されるため）
- `preferences` が false の項目はパラメータを省略する
- `preferences` が true の項目は `1` を送る
- APIキーがURLに含まれる（ログには出さない）

### 外部APIエラー（`search.ts`）

- `results.error` code 1000 → 502
- 同 2000 → 502 かつ `upstreamErrorCode` をログ出力
- 同 3000 → 502 かつ `upstreamErrorCode` をログ出力
- `fetch` reject → 502
- 5秒タイムアウト → 504
- リトライが発生しない（`fetch` 呼出が1回）

### レスポンス整形（`mapper.ts`）

- 20件の正常レスポンスがそのままの順序で返る
- 0件レスポンスが 200 / `hasMore: false` で返る
- `photoUrl` 欠落時に `null` になる
- `budgetText` 欠落時に `null` になる
- `lat` / `lng` 欠落・非数値時に店舗は残り、`walkMinutes` が `null` になる
- **`lat` / `lng` / `distanceMeters` がレスポンスに含まれない**

### ページング（`mapper.ts`）

- `resultsStart=1 / returned=50 / available=120` → `nextStart=51 / hasMore=true`
- `resultsStart=101 / returned=20 / available=120` → `nextStart=121 / hasMore=false`
- 0件 → `nextStart=1 / hasMore=false`
- `nextStart` が `MAX_START` を超える → `hasMore=false`（`available` が十分でも）

### 距離・徒歩時間（`geo.ts`）

- 既知の2地点間のHaversine距離が許容誤差内
- 同一地点 → 距離0 / `walkMinutes` が1（0にしない）
- 400mの直線距離 → 歩行距離520m → 7分

### ログ（`index.ts`）

- ログ出力に `HOTPEPPER_API_KEY` が含まれない
- ログ出力に `lat` / `lng` が含まれない

## 5. F/Eテスト観点

### 純粋関数

`shuffleInChunks`:

- 出力の要素集合が入力と一致する（欠落・重複なし）
- ブロック境界を越えて要素が移動しない（先頭10件の集合が入力の先頭10件と一致）
- 端数ブロック（55件 → 最後は5件）が壊れない
- 空配列 / 1件で例外にならない

`applyRelax`:

- level 0 → 条件が変わらない
- level 1 → `preferences` が全false、他は不変
- level 2 → level 1 に加えて `genreCode` が null
- level 3 → level 2 に加えて `range` が +1
- `range = 4` で level 3 → `range` は4のまま（上限を超えない）
- level 4 → level 3 に加えて `budgetMax` が null
- 元の `condition` オブジェクトを破壊しない

`nextRelaxLevel`:

- こだわり未設定 → level 1 をスキップする
- ジャンルおまかせ → level 2 をスキップする
- `range = 4` → level 3 をスキップする
- `budgetMax = null` → level 4 をスキップする
- 緩和できる段階が残っていない → `null`（CTAを出さない）

`mergeUniqueShops`:

- `shownIds` / `currentShop` / `queue` と重複する店舗を除外する
- 重複が無ければ全件追加される

### Storage（`storage.ts`）

- `loadSession` がTTL（2時間）超過のセッションを破棄して `null` を返す
- `loadSession` がTTL内のセッションを返す
- `loadGeo` が30分超過の現在地を破棄する
- 破損JSONで例外を投げず、該当キーを削除して初期値を返す
- `QuotaExceededError` を握りつぶして継続する
- Web Storage が利用不可の環境で例外を投げない
- `tsugidoko:*` 以外のキーへ書き込まない

### 履歴（`storage.ts`）

- 20件を超えると最古が削除される
- 同一 `shopId` の再OKで古い方が消えて先頭に来る
- `photoUrl` が保存されない

### 提示制御（`search.ts` / reducer）

- 初回検索で1店舗だけが表示される
- NGで別の店舗が表示される
- 同一セッションで同じ店舗が2度表示されない
- `queue.length <= 8 && hasMore` でprefetchが発火する
- prefetch中に再度条件を満たしてもprefetchが二重発火しない
- `queue` 空 + `hasMore: false` → `noCandidate` になる
- 検索結果0件 かつ `hasMore: false` → `noCandidate` になる
- 検索結果0件 でも `hasMore: true` なら `noCandidate` にせず先読みへ回す
- 緩和での再検索は `shownIds` を引き継ぎ、トップからの検索では捨てる
- 通信中に「さがす」を連打しても送信が1回

### コンポーネント

- 予算スライダーが離散値にスナップし、`aria-valuetext` が表示ラベルと一致する
- 距離スライダーが4段階
- ジャンルチップが単一選択で、選択中に `aria-pressed="true"` が付く
- こだわりAccordionが開閉し、選択件数が表示される
- OKボタンが `<a href={hotpepperUrl} target="_blank" rel="noopener noreferrer">` である
- OKクリックで履歴が保存され、`preventDefault` が呼ばれない
- トップ画面の「さがす」直上に検索範囲テキストが表示される
- ヘッダーのアプリ名をタップするとトップ画面へ戻り、条件が保たれる
- 結果画面に検索範囲テキストが表示される
- 緩和後の結果画面に緩和通知が表示される
- `relaxLevel = 4` のとき候補なし画面に緩和CTAが出ない
- 各画面にHotPepperクレジットが表示される（トップ / 結果 / 履歴）
- 位置情報拒否時に再試行CTAが出る
- 「人数」ステッパーが存在しない
- `walkMinutes` / `budgetText` が `null` の店舗で、その行が表示されない（結果画面・履歴シート）
- 1ページ目が全滅しても、続きがあれば次ページの候補が表示される

## 6. CI

`.github/workflows/ci.yml`

トリガー: `pull_request` / `push`（デフォルトブランチ）

```yaml
jobs:
  verify:
    steps:
      - checkout
      - setup-node (LTS, cache: npm)
      - npm ci
      - npm run lint
      - npm run format:check
      - npm run typecheck
      - npm run test
      - npm run test:worker
      - npm run build
```

- すべて1ジョブで直列実行する。MVP規模では並列化の利得より設定の単純さを優先する
- `npm run build` まで含め、型エラーとビルド失敗をPR時点で検出する
- CIはHotPepper APIへ到達しない。外部API呼出はすべてモックする

## 7. デプロイ

`.github/workflows/deploy.yml`

- トリガー: デフォルトブランチへの `push`、および手動実行（`workflow_dispatch`）
- `cloudflare/wrangler-action` で `wrangler deploy`
- `HOTPEPPER_API_KEY` は GitHub Secrets から Worker の Secret へ反映する。
  ターミナルでの `wrangler secret put` は不要
- Secrets が未登録のうちはデプロイをスキップして成功で終わる。
  設定前から `main` が赤くなるのを避けるため

必要な GitHub Secrets:

| 名前 | 用途 |
|---|---|
| `CLOUDFLARE_API_TOKEN` | Cloudflareへのデプロイ。テンプレート「Edit Cloudflare Workers」で作る |
| `CLOUDFLARE_ACCOUNT_ID` | デプロイ先アカウント |
| `HOTPEPPER_API_KEY` | Worker の Secret へ反映される |

`ALLOWED_ORIGIN` は設定しない。未設定ならWorker自身のオリジンを許可する（BE-001 §5）。

### 予算マスタの生成

`.github/workflows/gen-budget.yml`

手動実行（`workflow_dispatch`）で `npm run gen:budget` を走らせ、生成物を `main` へコミットする。
ターミナルが無い環境でもマスタを更新できるようにするため。
生成後に `typecheck` と `test:worker` を通してからコミットする。

## 8. 手動確認項目

自動テストで担保しない項目。リリース前に実機で確認する。

| # | 項目 | 端末 |
|---|---|---|
| 1 | ホーム画面へ追加できる | iOS Safari / Android Chrome |
| 2 | 機内モードでアプリシェルが起動する | 両方 |
| 3 | 「さがす」押下時に位置情報ダイアログが出る | 両方 |
| 4 | 位置情報を拒否 → 再試行で許可できる | 両方 |
| 5 | OKでHotPepperがブロックされずに開く | **iOS Safari（PWA）** |
| 6 | 他アプリへ切替 → 30分後に復帰してもセッションが残る | **iOS（PWA）** |
| 7 | 2時間経過後にセッションが破棄されて初期状態になる | 両方 |
| 8 | 別オリジンから `/api/search` を叩くと403 | curl |
| 9 | 1分間に30回超のリクエストで429になる | curl |
| 10 | DevToolsのNetworkにAPIキーが出ない | デスクトップ |

5 と 6 はiOS固有の挙動（ポップアップブロック / PWAの破棄）を狙った確認であり、省略しない。
