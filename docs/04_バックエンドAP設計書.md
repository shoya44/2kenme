- 文書ID: BE-001

- 更新日: 2026-09-19
- 技術: Cloudflare Worker + TypeScript

## 1. 責務

B/EはHotPepper APIとの境界に限定する。

```text
受け取る
↓
Originを検証する
↓
入力を検証する
↓
予算上限をHotPepper予算コードへ変換する
↓
HotPepperへ問い合わせる
↓
アプリ用に整形する
↓
返す
```

B/Eでは提示制御・履歴・セッション・DB・cacheを持たない。

HotPepper固有のコード体系はB/Eに閉じ込め、F/Eへ漏らさない。

## 2. API一覧

| Method | Path | 用途 |
|---|---|---|
| POST | `/api/search` | 現在地・条件から店舗候補を取得 |

## 3. Request

```typescript
interface SearchRequest {
  lat: number;
  lng: number;
  range: 1 | 2 | 3 | 4;
  /** 1人あたりの予算上限（円）。null は上限なし */
  budgetMax: number | null;
  genreCode: string | null;
  preferences: {
    privateRoom: boolean;
    freeDrink: boolean;
    midnight: boolean;
  };
  start: number;
}
```

人数（`partySize` / `party_capacity`）は扱わない（REQ-001 §6.5）。

## 4. 入力検証

| 項目 | 条件 |
|---|---|
| lat | -90〜90 の有限数 |
| lng | -180〜180 の有限数 |
| range | 1〜4 |
| budgetMax | null または `[2000, 3000, 4000, 5000, 7000, 10000]` のいずれか |
| genreCode | null または許可済みジャンルコード（`G001` `G002` `G012` `G013` `G014`） |
| preferences | boolean 3項目 |
| start | 1以上の整数 |

不正時は `400`。

`genreCode` はallowlist照合とする。HotPepperへ任意文字列を通さない。

## 5. Origin検証とレート制限

### Origin検証

`/api/search` は以下を満たす場合のみ処理する。

- `Origin` ヘッダが存在し、許可オリジンと完全一致すること

許可オリジンは `env.ALLOWED_ORIGIN`。**未設定の場合は Worker 自身のオリジン**（リクエストURLのオリジン）を使う。

静的アセットとAPIは同じWorkerが配信するため、本番で許可すべきオリジンはWorker自身のオリジンに一致する。既定でそれを使うことで、デプロイ時の設定を不要にし、設定漏れで全リクエストが403になる事故も防ぐ。F/Eを別ポートで動かす開発時だけ `.dev.vars` で明示する。

不一致・欠落時は `403`。CORSヘッダは返さない（同一オリジン前提のため）。

これはAPIキー秘匿とは別の目的で、**第三者によるHotPepperコール枠の消費を防ぐ**ために必要。

### レート制限

Cloudflare Rate Limiting Rules で `/api/*` に対して設定する。

| 項目 | 値 |
|---|---|
| 特性 | クライアントIP |
| 期間 | 60秒 |
| 上限 | 30リクエスト |
| 動作 | Block（429） |

Worker側の実装は不要。設定値はインフラ側の管理対象とし、本書を根拠とする。

## 6. 予算上限 → 予算コード変換

### 方針

HotPepperの予算コード（`B001` 等）の対応表は**ハードコードしない**。検索用ディナー予算マスタAPIから取得してビルド時に生成する。

```text
scripts/gen-budget-master.ts
  ↓ 検索用ディナー予算マスタAPI
worker/budget-master.generated.ts
```

```typescript
interface BudgetMasterEntry {
  code: string;
  name: string;
  /** 予算帯の下限（円） */
  min: number;
  /** 予算帯の上限（円）。最上位帯など上限なしの場合は null */
  max: number | null;
}
```

生成スクリプトはマスタの `name`（例: `2001〜3000円`）を解析して `min` / `max` を導出する。**解析できない項目が1件でもあればビルドを失敗させる**（無言で予算帯が欠落するのを防ぐため）。

マスタは頻繁に変わらないため生成物をコミットし、CIで再生成しての差分検知は行わない。

### 変換ルール

```typescript
function toBudgetCodes(budgetMax: number | null): string[]
```

- `budgetMax === null` → 空配列（`budget` パラメータを送らない）
- それ以外 → `entry.max !== null && entry.max <= budgetMax` を満たす全コード

例: `budgetMax = 3000` なら、上限が3,000円以下の予算帯すべて（〜500円 / 501〜1,000円 / … / 2,001〜3,000円）を対象とする。

変換結果が空配列（＝該当コードなし）になった場合も `budget` を送らない。

> 要確認: `budget` に指定できるコード数の上限。上限がある場合は、`budgetMax` に近い側から上限個数だけ送る（安い帯ほど2軒目の候補として落としにくいため、切り捨てるのは下位帯とする）。実装前にリファレンスで確認すること。

## 7. HotPepperパラメータ

固定:

```text
format=json
datum=world
count=50
order=4
```

`order=4`（おすすめ順）を**明示指定**する。HotPepperのソート順に距離順は存在せず、既定値に依存しないよう明示する。`range` で範囲が上限2kmに制限されるため、おすすめ順でも「近い店」の要件は満たせる。

動的:

```text
key
lat
lng
range
budget      （カンマ区切り。budgetMax が null のときは送らない）
genre       （おまかせのときは送らない）
private_room
free_drink
midnight
start
```

boolean条件がfalseの場合はパラメータを省略する。

## 9. 外部APIエラー

HotPepperはAPIエラー時もHTTP `200 OK` を返すため、必ず `results.error` を確認する。

| Code | 内容 | アプリHTTP | ログレベル |
|---|---|---|---|
| 1000 | HotPepperサーバー障害 | 502 | warn |
| 2000 | APIキー/IP認証 | 502 | error |
| 3000 | パラメータ不正 | 502 | error |

2000 / 3000 は**自アプリの不具合**を示す。502に丸めてユーザーへは同一表示とするが、`upstreamErrorCode` をログへ残し、アラートの対象とする。

## 10. タイムアウト

HotPepper通信は約5秒で打ち切る（`AbortSignal.timeout(5000)`）。

| 状況 | Status |
|---|---|
| 正常 | 200 |
| fetch失敗 | 502 |
| HotPepper error | 502 |
| timeout | 504 |

自動リトライしない。

## 11. Response

```typescript
interface SearchResponse {
  shops: Shop[];
  paging: {
    nextStart: number;
    hasMore: boolean;
  };
}

interface Shop {
  id: string;
  name: string;
  photoUrl: string | null;
  hotpepperUrl: string;
  budgetText: string | null;
  walkMinutes: number;
}
```

`shops` はHotPepperの返却順（おすすめ順）を保持する。シャッフルはF/Eが行う。

緯度経度・直線距離は返さない。結果画面で使用せず、クライアントへ渡す必要がないため（プライバシー方針とも一貫）。

## 14. 徒歩時間

Haversine式で現在地と店舗の直線距離を算出する。

```text
歩行距離 = 直線距離 × 1.3
walkMinutes = max(1, ceil(歩行距離 / 80))
```

- 係数1.3は、直線距離に対する市街地の道なり距離の一般的な概算倍率（迂回率）。厳密な経路計算は行わない
- 分速80mは不動産表示で慣例的に用いられる徒歩速度
- HotPepperの緯度経度は店舗の代表点であり誤差を含むため、UI表記は「徒歩 **約**4分」とし、断定しない

根拠は `worker/geo.ts` のコメントとして残す。

## 20. 環境変数

| Name | Type | 用途 |
|---|---|---|
| `HOTPEPPER_API_KEY` | Secret | HotPepper APIキー |
| `ALLOWED_ORIGIN` | Var（任意） | 許可するOrigin。未設定ならWorker自身のオリジン。開発時のみ指定する |
| `HOTPEPPER_ENDPOINT` | Var（任意） | HotPepperのエンドポイント差し替え。開発時のみ。未設定なら本番を使う |

`HOTPEPPER_API_KEY` が未設定の場合は上流を叩かず `500` を返す。Secretの登録漏れを
上流の認証エラー（2000）に化けさせず、設定不備として切り分けられるようにするため。
