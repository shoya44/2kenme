# つぎどこ — データ設計書

- 文書ID: DATA-001
- 版: 2.1
- 更新日: 2026-09-23
- 対象: MVP

## 1. 方針

サーバーDBは使用しない。

```text
localStorage
sessionStorage
```

だけを使用する。

IndexedDB・永続検索キャッシュはMVPでは使用しない。

## 2. 保存データ一覧

| Key | 保存先 | 用途 | 保持 |
|---|---|---|---|
| `tsugidoko:defaults` | localStorage | 前回検索条件 | 明示削除まで |
| `tsugidoko:history` | localStorage | OKした店舗 | 最大20件 |
| `tsugidoko:session` | localStorage | 現在の提示状態 | 離脱から5分 / 検索開始から2時間 |
| `tsugidoko:geo` | sessionStorage | 現在地 | タブ終了まで（鮮度5分） |
| `tsugidoko:geo-granted` | localStorage | 位置情報の許可実績（座標なし） | 明示削除まで |

現在地（座標）は `tsugidoko:geo`（sessionStorage）にのみ保持し、localStorageへは保存しない。localStorageへ置くのは「許可が済んでいる」という事実だけで、座標は含まない。

### セッションをlocalStorageへ置く理由

iOSのホーム画面PWAはバックグラウンドで頻繁に破棄され、sessionStorageが失われる。「店を探しながら他アプリを開いて戻る」という本アプリの中心的な利用文脈でそのまま状態が消えるため、セッションはTTL付きでlocalStorageへ保存する。

現在地のみはlocalStorageへ置かないため、復帰後の追加取得時に現在地が無ければ再取得する。

Shopから緯度経度を除いた（BE-001 §11）ことで、セッションをlocalStorageへ置いても位置情報が永続化されない。

## 3. SearchCondition

```typescript
interface SearchCondition {
  /** 1人あたりの予算上限（円）。null は上限なし */
  budgetMax: number | null;
  /** 予算が未登録の店も候補に含めるか（REQ-001 §6.1） */
  includeUnknownBudget: boolean;
  genreCode: string | null;
  preferences: {
    privateRoom: boolean;
    freeDrink: boolean;
    midnight: boolean;
  };
  range: 1 | 2 | 3 | 4;
}
```

HotPepperの予算コードはF/Eに持たない（BE-001 §6）。

## 4. defaults

```text
tsugidoko:defaults
```

```typescript
type SearchDefaults = SearchCondition;
```

例:

```json
{
  "budgetMax": 4000,
  "includeUnknownBudget": true,
  "genreCode": "G001",
  "preferences": {
    "privateRoom": false,
    "freeDrink": true,
    "midnight": true
  },
  "range": 3
}
```

保存: 「さがす」押下時。  
読込: App起動時。`budgetMax` / `genreCode` / `range` を許可値（§17）と照合し、外れていれば全体を初期値へ戻す。旧バージョンが書いた選択肢外の値をそのまま送ると Worker が `400` を返し、「店舗を取得できませんでした」から抜け出せなくなるため。

緩和（`relaxLevel`）は `defaults` へ保存しない。緩和はその場限りの操作であり、次回起動時に引き継がない。

## 5. Shop

```typescript
interface Shop {
  id: string;
  name: string;
  photoUrl: string | null;
  hotpepperUrl: string;
  budgetText: string | null;
  /** 算出できない場合は null */
  walkMinutes: number | null;
  /** 営業時間。未登録なら null */
  openText: string | null;
  /** 定休日。未登録なら null */
  closedText: string | null;
}
```

営業時間・定休日は履歴へ保存しない（HistoryEntry）。店舗側で変わる情報であり、履歴は「いつどこに決めたか」の記録に留める。

## 6. GeoPoint

```text
tsugidoko:geo
```

```typescript
interface GeoPoint {
  lat: number;
  lng: number;
  acquiredAt: number;
}
```

sessionStorageのみ。`acquiredAt` から5分（`GEO_TTL_MS`）以上経過していれば再取得する。移動したあとの再検索で古い地点を使わないため、短く取る。

### tsugidoko:geo-granted

```text
tsugidoko:geo-granted  // true のみ
```

位置情報の取得に一度成功したことを示すフラグ。localStorageに置く。座標は含まない。

起動時に許可ダイアログを出さずに現在地を先出しできるかの判断に使う（FE-001 §21）。Safari は Permissions API で geolocation を照会できないため、この実績で代える。

## 7. session

```text
tsugidoko:session
```

```typescript
interface SearchSession {
  condition: SearchCondition;
  relaxLevel: 0 | 1 | 2 | 3 | 4;
  currentShop: Shop | null;
  queue: Shop[];
  shownIds: string[];
  nextStart: number;
  hasMore: boolean;
  startedAt: number;
}
```

現在地は含めない。

### 有効期間

読込時に次のどちらかに当たれば破棄し、トップ画面から始める。判定は `services/storage.ts` の `loadSession()` で行う。

| 基準 | 期間 | 目的 |
|---|---|---|
| `lastActiveAt`（最後の操作・離脱時刻）から | 5分（`RESUME_WINDOW_MS`） | 「地図やメッセージを見て戻る」間だけ提示中の店を保つ |
| `startedAt`（検索開始）から | 2時間（`SESSION_TTL_MS`） | 開きっぱなしの画面で古い抽選が続かないようにする |

iOSのPWAはアプリを切り替えただけでも破棄されるため、「ユーザーが開き直した」のと「OSが破棄して再起動した」は区別できない。離脱からの経過時間で代える。

`lastActiveAt` は `saveSession()` が保存のたびに打ち、加えて画面が `hidden` になったとき `touchSession()` で打ち直す（結果画面を開いたまま放置して離脱した場合に、最後の操作ではなく離れた時刻を基準にするため）。

このフィールドを持たない旧バージョンのセッションは `startedAt` で判断する。

## 8. session更新

- 初回検索成功: 新規作成
- NG: `currentShop / queue / shownIds` 更新
- 追加取得: `queue / nextStart / hasMore` 更新
- 条件緩和: `relaxLevel` 更新後、既存sessionを破棄して新規作成
- 再検索: 既存session破棄後に新規作成

## 9. 重複ルール

追加候補の店舗IDが以下のいずれかに存在する場合は除外する。

```text
shownIds
currentShop.id
queue[].id
```

実装時は `Set<string>` を利用してよい。

HotPepperはページ間で同一店舗を返し得るため、重複排除後の実効取得件数は要求件数を下回る。先読み閾値を8件としているのはこのため（FE-001 §19）。

## 10. HistoryEntry

```text
tsugidoko:history
```

```typescript
interface HistoryEntry {
  shopId: string;
  name: string;
  hotpepperUrl: string;
  budgetText: string | null;
  /** 算出できない場合は null */
  walkMinutes: number | null;
  decidedAt: number;
}
```

店舗写真は履歴へ保存しない。緯度経度はそもそもクライアントへ渡らない。

履歴シートではサムネイルを表示せず、店名・徒歩時間・予算感・日付のテキストのみを並べる。徒歩時間・予算感は値がある項目だけを並べる（`null` の項目は表記しない）。

## 11. 履歴ルール

- 最大20件
- 新しい順
- 同一 `shopId` は1件のみ
- 再度OKした場合は古い同一店舗を削除して先頭へ
- 21件目追加時は最古を削除

## 12. Storage操作

`services/storage.ts` だけがWeb Storage APIへアクセスする。

```typescript
loadDefaults()
saveDefaults()
clearDefaults()

loadHistory()
addHistory()
clearHistory()

loadSession()   // TTL判定を含む
saveSession()
clearSession()

loadGeo()       // acquiredAt の鮮度判定を含む
saveGeo()
clearGeo()

markGeoGranted()  // 許可実績。座標は含まない
hasGeoGranted()
clearGeoGranted()

loadPasscode()
savePasscode()
clearPasscode()
```

UIから直接 `localStorage` / `sessionStorage` を触らない。

### tsugidoko:passcode

```text
tsugidoko:passcode
```

`/api/search` の合言葉（BE-001 §5）。毎回入力させないため localStorage に置く。

- 個人認証ではなく身内向けの共有秘密。端末に平文で残るため、強度は「その端末を使える人」までしか担保しない
- サーバーが `403` を返したら破棄し、入力画面へ戻す（古い合言葉を持ち続けない）
- 文字列以外・空文字は未保存として扱う

## 13. JSON破損 / 容量超過

`JSON.parse` 失敗時:

```text
該当Key削除
↓
初期値で継続
```

`QuotaExceededError` および Web Storage 自体が利用できない環境（プライベートブラウズ等）でも、書き込み失敗を握りつぶしてアプリを継続する。永続化は本アプリの必須機能ではない。

アプリ全体を停止しない。

## 14. プライバシー

### localStorageへ保存しない

- 緯度
- 経度

### クライアントへ渡さない

- 店舗の緯度経度（BE-001 §11）

### サーバーへ保存しない

- 現在地
- OK / NG履歴
- ユーザー設定
- 店舗履歴

B/Eはステートレス。

## 15. PWAとの関係

```text
Service Worker
  └─ アプリシェル

localStorage
  ├─ tsugidoko:defaults
  ├─ tsugidoko:history
  ├─ tsugidoko:session （離脱から5分 / 開始から2時間）
  └─ tsugidoko:geo-granted （許可実績。座標は含まない）

sessionStorage
  └─ tsugidoko:geo （鮮度5分）
```

API店舗情報の永続オフラインキャッシュはMVP対象外。

## 16. 型共有

API I/F型:

```text
shared/api-types.ts
```

`SearchRequest` / `SearchResponse` / `Shop` を共有する。Storage内部型（`SearchSession` / `HistoryEntry` / `GeoPoint`）はF/E側だけで管理し、B/Eへ共有しない。

## 17. 整合性ルール

| データ | ルール |
|---|---|
| budgetMax | null または `[2000,3000,4000,5000,7000,10000]` |
| includeUnknownBudget | boolean（既定 true） |
| genreCode | null または許可済みジャンルコード |
| range | 1〜4 |
| relaxLevel | 0〜4 |
| shownIds | 重複なし |
| queue | shownIds / currentShopと重複なし |
| history | 最大20件 / shopId重複なし |
| session | lastActiveAt から5分以内 かつ startedAt から2時間以内 |

## 18. 将来の移行条件

以下が必要になった場合のみIndexedDB等を検討する。

- 大量のお気に入り
- 大量の履歴
- 店舗情報の長期オフライン保持
- 複雑な検索キャッシュ
- クラウド同期
