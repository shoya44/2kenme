# つぎどこ — 要件定義書

- 文書ID: REQ-001
- 版: 2.0
- 更新日: 2026-09-19
- 対象: MVP

## 1. 目的

飲み会の2軒目を決める際の「候補が多くて決められない」という迷いを減らす。

ユーザーは必要最小限の条件を設定し、**近くの評判の良い店を1店舗だけ**受け取る。候補が合わなければNGで次の1店舗へ進み、合えばOKで決定する。

```text
条件を設定
  ↓
さがす
  ↓
1店舗だけ表示
  ↓
NG → 次の1店舗
OK → 決定
```

一覧・ランキング・比較を行わないことをプロダクトの特徴とする。

## 2. プロダクト名

- 名称: **つぎどこ**
- タグライン: 2軒目を、1軒だけ。
- 内部識別子: `tsugidoko`

## 3. 対象ユーザー

- 飲み会後に近場の2軒目を探したい人
- 店舗一覧を比較するより短時間で決めたい人
- スマートフォンで片手操作したい人

## 4. 提供形態

- スマートフォン優先のPWA
- ホーム画面へ追加可能
- アプリ本体はオフライン起動可能
- 店舗検索にはネットワーク接続が必要
- 店舗情報はHotPepperグルメサーチAPIを利用

## 5. 機能要件

| ID | 機能 | 要件 |
|---|---|---|
| F-01 | 現在地取得 | Geolocation APIで取得する。取得は「さがす」押下時に開始する |
| F-02 | 条件設定 | 予算上限・ジャンル・こだわり・距離を設定できる |
| F-03 | 検索 | 条件に合う近隣店舗をおすすめ順に取得し、1店舗だけ表示する |
| F-04 | NG | 同一セッションで未表示の次候補を表示する |
| F-05 | OK | 店舗を履歴へ保存し、HotPepper店舗詳細へ遷移する |
| F-06 | 重複排除 | 同一セッションで同じ店舗を再表示しない |
| F-07 | 追加取得 | 候補が少なくなったら次の検索結果を先読みする |
| F-08 | 条件復元 | 前回使用した検索条件を次回起動時に復元する |
| F-09 | 履歴 | OKした店舗を最大20件保存する |
| F-10 | 店舗詳細 | HotPepper店舗URLを開ける |
| F-11 | 連絡先導線 | 電話番号を直接保持せず、HotPepper店舗詳細から確認する |
| F-12 | 候補0件 | 条件を1段階ずつ緩和して再検索できる |
| F-13 | 候補切れ | 候補を出し切った場合は「候補なし」として扱う |
| F-14 | 検索範囲の明示 | 「現在地から半径◯◯以内」をトップ画面と結果画面に表示する |
| F-15 | PWA | インストール、アプリシェルのオフライン起動に対応する |
| F-16 | セッション復帰 | アプリがバックグラウンドで破棄されても、一定時間内なら抽選状態を復帰する |

## 6. 検索条件

### 6.1 予算（上限指定）

- UI: 離散スライダー
- **範囲指定ではなく上限指定**とする（「3,001〜4,000円の帯」ではなく「4,000円以内」）
- 1人あたりのディナー予算を基準とする

| index | 表示 | 内部値 `budgetMax` |
|---|---|---|
| 0 | 2,000円以内 | 2000 |
| 1 | 3,000円以内 | 3000 |
| 2 | 4,000円以内 | 4000 |
| 3 | 5,000円以内 | 5000 |
| 4 | 7,000円以内 | 7000 |
| 5 | 10,000円以内 | 10000 |
| 6 | 指定なし | null |

`budgetMax = null` は上限なしを意味し、10,000円超の店舗も対象に含む。

HotPepperの予算コードへの変換はB/Eが行い、F/Eはコードを持たない。

#### 予算未登録の店を含める（`includeUnknownBudget`）

HotPepperの予算コードは店舗側の登録制で、**未登録の店舗が相当数ある**。予算で絞り込むと、この未登録店がすべて候補から外れ、候補数が大きく減る。

- UI: 予算スライダーの下にチェックボックス「予算未登録の店も含める」
- 初期値: ON（候補の多さを優先する）
- `budgetMax = null`（指定なし）のときは絞り込み自体が発生しないため、チェックボックスは無効化する
- ON のとき: 予算での絞り込みを行わない。予算未登録の店も、上限を超える店も候補に含む
- OFF のとき: 予算を登録していて、かつ上限以下の店だけに絞る

チェックボックスの下に、現在の挙動を説明する一文を常時表示する。

### 6.2 ジャンル

- UI: チップ
- 単一選択
- **HotPepperのジャンルマスタ（大ジャンル）に一致させる**

| 表示 | 内部値 `genreCode` |
|---|---|
| おまかせ | null |
| 居酒屋 | G001 |
| ダイニングバー・バル | G002 |
| バー・カクテル | G012 |
| ラーメン | G013 |
| カフェ・スイーツ | G014 |

「焼き鳥」等の小ジャンルはHotPepperのジャンルコードに存在しないため、MVPでは扱わない。

### 6.3 こだわり

初期状態は折りたたむ。

- 個室
- 飲み放題
- 23時以降営業

### 6.4 距離

- UI: 離散スライダー
- 300m / 500m / 1km / 2km

### 6.5 人数

MVPでは扱わない。HotPepperの `party_capacity` は「宴会収容人数の登録値」によるフィルタであり、未登録店舗が一律に除外されて候補が過度に減るため。

## 7. 画面要件

### 7.1 トップ画面

- 共通ヘッダー
- 予算スライダー（上限指定）
- ジャンルチップ
- こだわり条件（折りたたみ）

### 7.2 結果画面

表示を以下に限定する。

- 店舗写真
- 店名
- HotPepper URL
- 徒歩時間
- 予算感
- 連絡先導線
- 検索範囲（現在地から半径◯◯以内）
- 緩和通知（条件を緩和した場合のみ）
- NGボタン
- OKボタン
- 条件変更
- HotPepperクレジット

評価・レビュー・ランキング・大量のタグは表示しない。

### 7.3 補助UI

- メニュー
- 履歴
- エラー / 候補なしメッセージ

## 8. 提示ロジック要件

1. 現在地・条件でHotPepperから**おすすめ順**に最大50件を取得
2. 上位から10件ずつのブロック単位でシャッフルする
3. 先頭1件のみ表示
4. NG時は現在店舗を表示済みにする
5. 次候補を即表示
6. 残候補が8件以下なら次ページを先読み
7. 表示済みID・既存候補と重複する店舗を除外

ブロック単位シャッフルにより、「評判が良く近い店から提示する」順序を保ちながら、同じ条件で毎回同じ店だけが出ることを防ぐ。

同一セッションでは一度表示した店舗を再表示しない。

## 9. 候補なし時

以下の2ケースを同一の「候補なし」状態として扱う。

- 検索結果が0件
- 候補を出し切り、追加取得もできない

ユーザー操作により、以下の順で1段階ずつ緩和できる。

| relaxLevel | 緩和内容 |
|---|---|
| 0 | 緩和なし |
| 1 | こだわり条件を解除 |
| 2 | ジャンルを「おまかせ」 |
| 3 | 距離を1段階拡大 |
| 4 | 予算上限を「指定なし」 |

緩和後は、**何を緩和したかを結果画面に表示する**。全段階を緩和しても候補が無い場合は緩和CTAを出さない。

## 10. 非機能要件

### UX / デザイン

- スマートフォン片手操作
- 1画面1目的
- Apple HIGの考え方を参考
- ダークモード固定
- モノクロベース + 差し色1色
- 十分な余白
- 主要タップ領域は原則48px以上
- UIアイコンはSVGを使用
- 装飾目的のGlass表現は抑える

### 性能

- 検索APIは通常通信環境で数秒以内の結果表示を目標
- NG時、候補が手元にあれば通信なしで即切替

### セキュリティ

- APIキーをブラウザへ公開しない
- `/api/search` を同一オリジン以外から利用させない
- IP単位のレート制限により、外部APIのコール枠の消費を防ぐ

### プライバシー

- 現在地をサーバーDBへ保存しない
- 現在地をlocalStorageへ保存しない
- サーバー側で検索履歴を保持しない
- 緯度経度をクライアントの永続領域とログへ残さない

### 外部サービス規約

- HotPepperのデータを表示する全画面にクレジットを表示する

- 空席確認

- ルーレット
- 音声入力
- お気に入り
- クラウド同期
- 終電連動

## 12. 受入条件

- PWAとして起動・インストールできる
- 「さがす」押下時に現在地を取得できる
- 条件を指定して検索できる
- 結果は1店舗だけ表示される
- NGで別店舗が表示される
- 同一セッションで店舗が重複しない
- OKで履歴へ保存され、HotPepper店舗ページが開く
- 前回条件を復元できる
- 履歴を最大20件保持できる
- 検索結果0件で「候補なし」が表示される
- 候補を出し切った場合も「候補なし」が表示される
- 条件緩和ができ、緩和内容が表示される
- 検索範囲がトップ画面と結果画面に表示される
- アプリ再起動後、2時間以内なら抽選状態が復帰する
- 全画面にHotPepperクレジットが表示される
- APIキーがブラウザへ露出しない
- 現在地が永続保存されない
- 別オリジンから `/api/search` を呼べない
