# つぎどこ — 基本設計書

- 文書ID: BAS-001
- 版: 2.0
- 更新日: 2026-09-19
- 対象: MVP

## 1. 設計方針

MVPでは、機能追加よりも**理解しやすさ・変更しやすさ・疎結合**を優先する。

責務は以下に分離する。

```text
UI
検索
保存
外部API境界
```

不要なフレームワーク、サーバーDB、複雑な状態管理層は設けない。

HotPepper固有の値（ジャンルコード・予算コード）は、F/Eに漏らさずB/E側へ閉じ込める。

## 2. 全体構成

```text
Browser / PWA
  └─ React
      ├─ UI
      ├─ 提示制御
      ├─ Geolocation
      └─ Web Storage
          │
          │ POST /api/search

  ├─ Origin検証 / 合言葉 / レート制限

          │
          ▼
HotPepper グルメサーチAPI
```

## 6. トップ画面

入力項目を以下の視覚パターンで揃える。

```text
ラベル        現在値
コントロール
```

| 項目 | UI | 内部値 |
|---|---|---|
| 予算 | 離散スライダー + チェックボックス | `budgetMax` / `includeUnknownBudget` |
| ジャンル | チップ | `genreCode` |
| こだわり | Accordion | boolean 3項目 |
| 距離 | 離散スライダー | `range` |

画面下部に検索範囲（現在地から半径◯◯以内でさがします）、「さがす」を主要CTAとして配置し、その下にHotPepperクレジットを小さく表示する。

「人数」ステッパーはMVPでは設けない（REQ-001 §6.5）。

## 10. 保存

### localStorage

```text
tsugidoko:defaults
tsugidoko:history
tsugidoko:session
```

`tsugidoko:session` は localStorage に置く。iOSのPWAはバックグラウンドで破棄されやすく、sessionStorageでは復帰できないため。復帰できるのは離脱から5分以内で、それを超えたらトップ画面から始める（DATA-001 §7）。

### sessionStorage

```text
tsugidoko:geo
```

現在地（座標）のみを保持する。鮮度は5分。localStorageへは保存しない（位置情報の許可実績を示すフラグだけは localStorage に置く。座標は含まない。DATA-001 §6）。

API検索結果の永続キャッシュはMVPでは持たない。

## 12. Cloudflare

```jsonc
{
  "name": "tsugidoko",
  "main": "worker/index.ts",
  // @cloudflare/vitest-pool-workers が同梱する workerd の対応上限に合わせる。
  // これより新しい日付にすると worker のテストが起動しない。
  "compatibility_date": "2026-08-22",
  "assets": {
    "directory": "./dist",
    "not_found_handling": "single-page-application",
    "run_worker_first": ["/api/*"]
  },
  "observability": { "enabled": true }
}
```

静的アセットは通常Workerを経由させない。

レート制限は Worker の Rate Limiting バインディング（`wrangler.jsonc` の `unsafe.bindings`）で行う。Cloudflare の Rate Limiting Rules はゾーン（独自ドメイン）の機能で `*.workers.dev` には適用できないため（詳細はBE-001 §5）。

## 14. エラー方針

| 状況 | UI |
|---|---|
| 位置情報取得失敗 | 現在地を取得できませんでした + 再試行 |
| 候補なし（0件 / 出し切り） | 候補が見つかりませんでした + 条件緩和CTA |
| 通信失敗 | 店舗を取得できませんでした + 再試行 |
| NG時追加取得失敗 | 既存候補があれば継続、無ければ再試行 |

## 15. セキュリティ / プライバシー

- APIキー: Cloudflare Secret（デプロイワークフローがGitHub Secretsから反映する）
- `/api/search` は `Origin` が自オリジンと一致する場合のみ許可（不一致は403）
- `/api/search` は合言葉（`X-App-Token`）が一致する場合のみ許可（不一致は403 / 未設定は500）
- IP単位のレート制限（Worker側のバインディング。60秒30回で429）
- 現在地: sessionStorageのみ
- Shopレスポンスに緯度経度を含めない
- サーバーDB: なし
- 検索履歴のサーバー保存: なし
- APIキー・緯度経度をログへ出さない

## 16. PWA

Service Worker:

- HTML / JS / CSS / アイコン等をキャッシュ
- APIレスポンスは永続キャッシュしない

オフライン時:

- アプリ起動: 可
- 条件編集: 可
- 履歴確認: 可
- 新規検索: 不可
