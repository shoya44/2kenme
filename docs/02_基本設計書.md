# 運命の1軒 — 基本設計書

- 文書ID: BAS-001
- 版: 1.0
- 更新日: 2026-09-19
- 対象: MVP

## 1. 設計方針

MVPでは、機能追加よりも**理解しやすさ・変更しやすさ・疎結合**を優先する。

責務は以下に分離する。

```text
UI
検索
保存
外部API境界
```

不要なフレームワーク、サーバーDB、複雑な状態管理層は設けない。

## 2. 全体構成

```text
Browser / PWA
  └─ React
      ├─ UI
      ├─ 抽選制御
      ├─ Geolocation
      └─ Web Storage
          │
          │ POST /api/search
          ▼
Cloudflare Worker / TypeScript
  ├─ 入力検証
  ├─ APIキー付与
  ├─ HotPepper呼出
  └─ レスポンス正規化
          │
          ▼
HotPepper グルメサーチAPI
```

## 3. 技術スタック

| 区分 | 採用 |
|---|---|
| F/E | Vite + React + TypeScript |
| 状態管理 | React Hooks / useReducer |
| Style | CSS Modules + CSS Variables |
| Icon | SVG / Lucide等 |
| PWA | vite-plugin-pwa |
| B/E | Cloudflare Worker + TypeScript |
| API通信 | fetch |
| 永続データ | localStorage |
| セッション | sessionStorage |
| 外部API | HotPepper グルメサーチAPI |
| Hosting | Cloudflare Workers + Static Assets |

## 6. トップ画面

入力項目を以下の視覚パターンで揃える。

```text
ラベル        現在値
コントロール
```

| 項目 | UI | 内部値 |
|---|---|---|
| 予算 | 離散スライダー | `budgetCode` |
| ジャンル | チップ | `genreCode` |
| 人数 | - / + | `partySize` |
| こだわり | Accordion | boolean 3項目 |
| 距離 | 離散スライダー | `range` |

画面下部に「抽選する」を主要CTAとして配置する。


## 8. 抽選フロー

### 初回

```text
抽選する
↓
条件保存
↓
現在地取得済み確認
↓
POST /api/search (start=1)
↓
最大20件
↓
shuffle
↓
queue保存
↓
1店舗表示
```

### NG

```text
現在店舗をshownIdsへ
↓
queueから次店舗
↓
即表示
↓
queue <= 5なら次ページ先読み
```

### 追加取得

```text
start=21, 41, 61...
↓
API検索
↓
shownIds / currentShop / queueと重複除外
↓
shuffle
↓
queue末尾へ追加
```

## 14. エラー方針

| 状況 | UI |
|---|---|
| 位置情報取得失敗 | 現在地を取得できませんでした + 再試行 |
| 候補0件 | 条件緩和CTA |
| 通信失敗 | 店舗を取得できませんでした + 再試行 |
| NG時追加取得失敗 | 既存候補があれば継続 |

## 15. セキュリティ / プライバシー

- APIキー: Cloudflare Secret
- 同一オリジン前提
- 現在地: sessionStorageのみ
- サーバーDB: なし
- 検索履歴のサーバー保存: なし
- APIキー・緯度経度をログへ出さない

## 16. PWA

Service Worker:

- HTML / JS / CSS / アイコン等をキャッシュ
- APIレスポンスは永続キャッシュしない

オフライン時:

- アプリ起動: 可
- 条件編集: 可
- 履歴確認: 可
- 新規検索: 不可
